DreamTrack Health
by Ela Unlu

How it started

I've been obsessed with dreams since I was 9. I kept journals, looked for patterns, wondered why some stayed vivid for days and others vanished on waking.

Then I watched a video where researchers were detecting Parkinson's and Alzheimer's from voice alone before any symptoms. I had one thought: what if I combined that with dreams? I could collect real longitudinal data from real people.

Around the same time, for personal reasons, my interest in genetic mutations grew. I started reading and noticed that some mutations had almost no published research on their links to neurodegeneration. The connection simply hadn't been studied. DreamTrack became a way to collect the data needed to change that.

I wrote those ideas down and built the app with Claude Code. Every threshold, every score has a citation behind it. This is what I made.

How it works

One recording. Two analyses.

Voice analysis
How you sound
The app measures 89 language-independent acoustic features: pitch variation, speech rate, pause patterns, vocal tremor. These are the same markers researchers use in clinical studies. Each feature maps to a specific condition with a citation from a peer-reviewed paper.
Dream analysis
What you say
Claude AI reads your dream narration and scores it for coherence, emotional tone, vocabulary complexity, and narrative structure. How you tell a story changes before your memory does.
Audio → librosa (89 language-independent acoustic features) → voice scores  |  Audio → Amazon Transcribe / Whisper → transcript → spaCy + Claude (dream NLP) → dream scores  |  both stored in PostgreSQL

Analysis · REM Sleep Behavior Disorder

How the RBD dream score is built

Two-layer analysis: rule-based keyword detection → Claude semantic override. Claude wins if available.

Layer 1 Keyword rules (Python)
Human attack words AND animal attack words both present
+0.40
Human OR animal attack (one type only)
+0.25
First-person motion verbs (run, flee, fight…) ≥ 2
≤+0.25
nightmare_indicator (valence < −0.3 AND arousal > 0.4 AND motion)
+0.20
emotional_arousal > 0.5
+0.15

Human attacks: chased, grabbed, attacked, strangled… Animal attacks: wolf, bear, lion, bitten, mauled… (only unambiguously threatening generic "dog" excluded)

Layer 2 Claude semantic scoring (overrides Layer 1)

Claude reads the full transcript and scores on the same 0–1 scale. It handles negation ("I was not being chased"), context ("the monster was friendly"), and ambiguous language that keyword rules miss.

Personalisation

How genetic mutations change the alert threshold

Scores range from 0 to 1. Below 0.30: normal. 0.30-0.55: mildly elevated, keep watching. Above 0.55: alert — consistent trend worth discussing with a doctor. For mutation carriers these thresholds are lowered based on published odds ratios.

effective alert threshold = 0.55 × (1 − reduction%)   |   max stacking cap: 55% reduction (threshold never falls below 0.25)
Mutation Condition Reduction Alert threshold No mutation baseline Source
APOE e4 het Alzheimer's 22% 0.429 0.55 Fortea, Nature Med 2024
APOE e4/e4 hom Alzheimer's 42% 0.319 0.55 Fortea, Nature Med 2024
PSEN1 / PSEN2 Alzheimer's 37% 0.347 0.55 DIAN 2023
LRRK2 G2019S Parkinson's 17% 0.456 0.55 Arora, JPD 2018
GBA severe (L444P) PD + Alzheimer's 27% / 30% 0.402 / 0.385 0.55 Parlar, Mov Disord 2023
MAPT FTD 32% 0.374 0.55 Bouzigues, J Neurol 2022
GRN / PGRN FTD 22% 0.429 0.55 GENFI, J Neurol Sci 2023
BAP1 Under research — neurodegeneration link unstudied 0% 0.55 (unchanged) 0.55 PMC 2025 (meningioma flag)

Family history also adjusts thresholds: 1 FDR with Alzheimer's -20%, 2+ FDR -32% (Neurology 2019 meta-analysis)  |  1 FDR with Parkinson's -25% (OR 3.23, Neurology Genetics 2024)  |  p-value threshold for trend significance: 0.05 (no mutation), 0.08 (any carrier), 0.10 (PSEN / APOE e4/e4)

How I built it

The process.

01
Reading the papers first
Before writing any code, I read the actual studies. Every threshold like f0_std < 20 Hz for Parkinson's came from a specific peer-reviewed paper. If I couldn't find a citation, I didn't add the feature. 25 papers total.
02
Building with Claude Code
I described the system architecture, the ML pipeline, and the scoring logic to Claude Code and built it iteratively. Frontend (Next.js), backend (FastAPI), the voice analysis pipeline, database schema, AWS infrastructure all of it.
03
Voice analysis is harder than it looks
Background noise, recording length, language all affect the signal. Minimum 15 seconds required (below this, F0 estimates are too noisy). Multi-language support via Claude translation before NLP analysis.
04
Not a medical device by design
Wellness monitoring, not diagnosis. Every score is labeled as an anomaly indicator. The GP report is designed to start a conversation with a doctor, not replace one.

What's next

The real research question.

The app works. The data is coming in. Now I want to use it for what I actually built it for.

The gap
Some genetic mutations have almost no research on neurodegeneration
Mutations like BAP1 are being tracked in cancer research but their possible connections to neurological change are almost completely unstudied. I couldn't find the papers because they don't exist yet. DreamTrack can collect longitudinal voice and dream data from carriers data that doesn't exist anywhere today.
The study
Can a daily recording (15 seconds and above) detect change in carriers over time?
The existing literature on speech biomarkers for Alzheimer's and Parkinson's was done in clinic settings, with small groups, using expensive equipment. DreamTrack is the first attempt to do this longitudinally, at scale, from a phone. I want to run a real pilot study using this as the data platform.

The app is live. The scoring system is grounded in 25 papers. The infrastructure is real. The next step is a research collaboration.
